# CAMPUS360 RAG service

A private Python service for the Student, Staff and Admin campus knowledge assistants. It is designed to sit behind the existing CAMPUS360 Supabase Edge Function and Cloudflare Worker gateway; it is not a replacement for the current portal authentication/session system.

## Security boundary

- The existing `campus-portal` Edge Function must authenticate the portal session first.
- Only after authentication should it call this service with `x-campus-ai-gateway`, `x-campus-user-id`, and `x-campus-role` headers. These headers must be generated by the Edge Function from its verified `u` profile, never copied from the browser request.
- Keep `AI_GATEWAY_SECRET` and `SUPABASE_SERVICE_ROLE_KEY` in server-side secrets only.
- Student retrieval is public knowledge only; staff retrieval is public + staff; admin retrieval is public + staff + admin.
- Complaint status is not RAG content. Continue to query the existing complaint APIs under their existing authorization rules.
- Do not ingest complaint records, reporter identities, evidence attachments, passwords, sessions, or private audit payloads into the knowledge corpus.

## Local development (Mac)

1. Install Python 3.12+, create a virtual environment and install requirements:

```bash
cd ai-service
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

2. Install Ollama and pull models:

```bash
ollama pull llama3.2
ollama pull nomic-embed-text
```

3. Set Supabase URL, service-role key and a random `AI_GATEWAY_SECRET` in `.env`. Do not commit .env.

4. Review and apply `../supabase/schema/ai-rag.sql` only after checking the existing project's migration history and active schema. The connected Supabase project was inactive when this code was prepared, so no live database migration was run.

5. Start the service:

```bash
set -a; source .env; set +a
uvicorn app.main:app --reload --port 8000
```

Health check: `GET http://localhost:8000/health`.

## API contract

### POST /chat

Requires trusted Edge Function headers:
- `x-campus-ai-gateway`: shared secret
- `x-campus-user-id`: authenticated CAMPUS360 profile ID
- `x-campus-role`: verified role (student/staff/admin)

JSON body: `{"question":"Where do I report a broken classroom fan?"}`

Returns answer text, source document/page/chunk references and a grounded flag.

### POST /ingest

Admin-only after the Edge Function has authenticated the admin. Send a multipart file plus:
- `x-document-title`
- `x-document-visibility`: public/staff/admin
- `x-document-department`

Supported formats: PDF, TXT, Markdown. Max file size: 15 MB.

## Model configuration

- Local: `LLM_PROVIDER=ollama`, `llama3.2` and `nomic-embed-text`.
- Hosted: `LLM_PROVIDER=openai` with server-side `OPENAI_API_KEY`. The selected embedding deployment must return 768 dimensions to match the database column; `text-embedding-3-small` is configured to request 768 dimensions.

## Deployment

Build the container and deploy it to a private container host. Restrict ingress to the CAMPUS360 Supabase Edge Function where possible. Configure secrets in the host's secret manager. Do not expose this service directly to browsers.

The existing Cloudflare Worker remains the public same-origin gateway. The remaining integration step is to add an `ai-chat` and admin-only `ai-ingest` action to `supabase/functions/campus-portal/index.ts`, invoking this service only after its existing session resolution and role checks. That small adapter is intentionally separated from this initial service scaffold so it can be reviewed against the current deployed Edge Function before updating the live gateway.

## Current limitations

This first scaffold uses a single-turn chat request; conversation persistence and rate limiting should be added at the Edge Function layer before production. The service does not mutate complaints or take admin actions. Add automated tests and an evaluation set before production rollout.
